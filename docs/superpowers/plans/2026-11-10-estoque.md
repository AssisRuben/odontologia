> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tornar o Estoque funcional: cadastro de produtos, entrada/saída/contagem com histórico, lote e validade opcionais por produto (saída FEFO), compra virando despesa paga ou a pagar, e lista de compras.

**Architecture:** Migração SQL (colunas novas em `inventory_items` e `inventory_movements`, tabela `inventory_lots`) com funções `SECURITY DEFINER` que fazem cada operação numa transação. Regras puras em `src/lib/estoque/`, repositório chamando as funções pelo cliente service role, rotas com `withClinic`, telas client-side que só chamam a API. Mesmo padrão de `src/lib/protese/` e `src/app/api/protese/`.

**Tech Stack:** Next.js 16.2.6 (route handlers com `params: Promise<…>`), Supabase/PostgREST, Tailwind v4 (tokens do novo layout), vitest, date-fns.

**Spec:** `docs/superpowers/specs/2026-11-10-estoque-design.md`

## Global Constraints

- Ler o guia relevante em `node_modules/next/dist/docs/` antes de escrever rotas/páginas (AGENTS.md).
- "Hoje": `todayYmd(new Date(), 'America/Sao_Paulo')` (`@/lib/messaging/time`); no SQL `(now() AT TIME ZONE 'America/Sao_Paulo')::date`.
- Dinheiro na API em centavos inteiros (`totalCostCents`, 0 < c ≤ 9 999 999 999); no banco `NUMERIC(10,2)` = centavos/100; tela com `parseReaisInput` (`@/lib/payments/money`) e `formatValor` (`@/lib/messaging/time`, recebe reais).
- Quantidades: inteiros; entrada/saída > 0; contagem ≥ 0.
- Tipos de movimento (`kind`): entrada `compra|devolucao|ajuste`; saída `uso|perda|vencido`; contagem grava `ajuste`. Rótulos: Compra, Devolução, Ajuste, Uso, Perda, Vencido.
- FEFO: `expires_at ASC NULLS LAST, created_at ASC`.
- "Vence em breve" = 0 ≤ dias para vencer ≤ 30; "vencido" = validade < hoje.
- Sugestão de compra: `max(0, alvo − quantity)`, `alvo = ideal_quantity ?? 2 × min_quantity`; só para itens ativos com `quantity <= min_quantity`.
- Despesa: `description` = `Compra: {produto} — {qtd} {unidade}` (máx. 200; sem unidade → sem o espaço final), `category 'material'`, `deduction_group 'custeio'`, sem dentista. Paga: `status 'paid'`, `payment_method` ∈ `dinheiro|cartao_credito|cartao_debito|pix|boleto`, `paid_at` = data às 12:00 America/Sao_Paulo, `due_date` = data. A pagar: `status 'pending'`, `due_date` obrigatória. Só `kind = 'compra'` gera despesa.
- Mensagens fixas: `Despesa de R$ {valor} lançada no Financeiro` (+ ` (a pagar)` se pendente); `Estoque insuficiente`; `Já existe um produto com esse nome`; `Este lote já está vencido`; `Ainda há {N} {unidade} em estoque`.
- Texto da lista de compras (WhatsApp):
  ```
  Lista de compras — {clínica} — {dd/MM/yyyy}

  *{fornecedor}*
  • {produto} — {qtd} {unidade}
  ```
  grupos por fornecedor em ordem alfabética, "Sem fornecedor" por último; itens por nome; linha em branco entre grupos.
- Cores só por tokens (`tinta*`, `linha*`, `porcelana*`, `petroleo*`, `gengiva*`) + `red-*`/`amber-*`/`green-*` apenas em selos e avisos.
- Funções SQL: `REVOKE ALL … FROM PUBLIC, anon, authenticated; GRANT EXECUTE … TO service_role`; toda consulta filtra `clinic_id`.
- Commits terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. vitest no Windows: PowerShell em `C:\Workspace\odontologia` (C maiúsculo).
