# A receber — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Substituir o placeholder da aba "Financeiro > Boletos" pela aba "A receber". Ela mostra todas as cobranças de pacientes em aberto, agrupadas em atraso, próximos 7 dias e depois, com totais, filtros e o último lembrete enviado pelo WhatsApp.

**Architecture:**
- Uma função pura (`src/lib/receber/agrupar.ts`) agrupa e soma as cobranças.
- O componente `AReceber` lê os dados pelo cliente Supabase do navegador, como o Painel, e reaproveita o `ListaPagamentos`, que ganha a prop opcional `extra`.
- O envio manual "Enviar link pelo WhatsApp" passa a gravar `payment_id` na mensagem, para contar como lembrete.
- Não há mudança no banco.

**Tech Stack:** Next.js 16.2.6, React, Supabase (cliente do navegador com RLS), Tailwind v4 (tokens tinta, linha, porcelana, petroleo), date-fns, vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-a-receber-design.md`

## Global Constraints

- Antes de escrever código Next, leia o guia relevante em `node_modules/next/dist/docs/` (AGENTS.md).
- **Nenhuma migração SQL.** Nenhuma dependência nova.
- **Cobranças em aberto:**
  - `status` em `['pending','overdue']`;
  - `payment_method` nulo ou diferente de `'convenio'`;
  - toda consulta usa `.eq('clinic_id', clinicId)`.
- **Mensagens que contam como lembrete:**
  - `status='sent'` e `direction='out'`;
  - `type` em `['charge','payment_due','manual']`;
  - `charge` e `payment_due` contam como "automático"; `manual` conta como "manual".
- **Datas:** "hoje" e as datas de `sent_at` são de São Paulo. Use `todayYmd` de `@/lib/messaging/time` e `dataSaoPaulo` de `@/lib/fluxo/calcular`.
- **Valores:** em centavos (`Math.round(amount*100)`), formatados com o formatador já usado no Financeiro. Vermelho `#EF4444` para atraso.
- **React:** a regra eslint react-hooks não permite `setState` síncrono no corpo de um effect.
- **Textos:** exatamente como na seção "Telas" da spec.
- **Commits:** terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Testes no Windows:** rode do PowerShell, com `Set-Location C:\Workspace\odontologia`, usando `npx vitest run <arquivo>`.

## Review Focus

1. **Cobrança que vence hoje:** aparece em "Próximos 7 dias", não em atraso (Task 2).
2. **Lembrete enviado às 23h30 em São Paulo** (02:30Z do dia seguinte): mostra a data de São Paulo (Task 2).
3. **"Marcar como pago" ou "Cancelar" na aba A receber:** a cobrança some da lista e os totais diminuem (Task 3, verificação na Task 4).
4. **Painel e outras telas que usam `ListaPagamentos` sem a prop `extra`:** continuam iguais (Task 3).
5. **Clínica com mais de 200 cobranças em aberto:** as notas fiscais e os lembretes são buscados em blocos, sem estourar o tamanho da URL (Task 3).

### Task 2: Agrupamento (função pura)

**Files:**
- Create: `src/lib/receber/agrupar.ts`
- Test: `tests/receber/agrupar.test.ts`

**Interfaces:**
- **Consumes:** o tipo `Payment` de `@/types` (usa `id`, `amount`, `status`, `due_date`, `payment_method`, `charge_kind`, `patient?.name`) e `dataSaoPaulo` de `@/lib/fluxo/calcular`.
- **Produces:**
  - `export type TipoReceber = 'todos'|'boleto'|'link'|'cartao'|'manual'`
  - `export type Lembrete = { payment_id: string; type: string; sent_at: string }`
  - `export type UltimoLembrete = { data: string; tipo: 'automatico'|'manual' }`
  - `export type ItemReceber = { pagamento: Payment; diasAtraso: number | null; ultimoLembrete: UltimoLembrete | null }`
  - `export type Totais = { totalCentavos: number; quantidade: number }`
  - `export type Receber = { grupos: { atraso: ItemReceber[]; proximos: ItemReceber[]; depois: ItemReceber[] }; totais: { atraso: Totais; proximos: Totais; total: Totais }; vazio: boolean }`
  - `export function tipoDe(p: Payment): Exclude<TipoReceber,'todos'>`
  - `export function agruparReceber(e: { hoje: string; pagamentos: Payment[]; lembretes: Lembrete[]; filtro: { busca: string; tipo: TipoReceber } }): Receber`

- [ ] **Step 1: Escrever os testes que falham** em `tests/receber/agrupar.test.ts`, com `hoje = '2026-11-10'`:
  - **Atraso:** vencimento em 2026-11-09 entra em `atraso`, com `diasAtraso` 1.
  - **Hoje:** vencimento em 2026-11-10 entra em `proximos`.
  - **Limite de 7 dias:** 2026-11-17 entra em `proximos`; 2026-11-18 entra em `depois`.
  - **Sem vencimento:** vai para o fim de `depois`.
  - **Ordem:** atraso do mais antigo para o mais novo; próximos e depois em ordem crescente.
  - **`tipoDe`:**
    - `carne` dá `'boleto'`;
    - `avulsa` com `payment_method 'boleto'` dá `'boleto'`;
    - `avulsa` com `'pix'` dá `'link'`;
    - `cartao_parcelado` dá `'cartao'`;
    - `manual` dá `'manual'`.
  - **Filtro `tipo: 'cartao'`:** deixa só os cartões, e os totais mudam junto.
  - **Busca:** `busca: 'joao'` encontra "João Silva"; `busca: '  '` mostra tudo.
  - **Totais:** `amount` 123.45 vira 12345 centavos. `total` soma os três grupos, e `atraso`/`proximos` somam só o próprio grupo.
  - **Último lembrete:**
    - dois lembretes da mesma cobrança: vence o de `sent_at` mais recente;
    - `type 'charge'` dá `'automatico'`; `'manual'` dá `'manual'`;
    - `sent_at '2026-11-10T02:30:00Z'` dá `data '2026-11-09'`;
    - cobrança sem lembrete dá `null`.
  - **Vazio:** `vazio` é `true` quando nada sobra depois do filtro.

- [ ] **Step 2: Rodar `npx vitest run tests/receber/agrupar.test.ts`.** Esperado: FAIL.

- [ ] **Step 3: Implementar `agrupar.ts`.**
  - A busca usa normalização NFD sem diacríticos, em minúsculas e sem espaços nas pontas.
  - `diasAtraso` é a diferença em dias entre `hoje` e `due_date`, usando `differenceInCalendarDays` com datas `parseISO`.

- [ ] **Step 4: Verificar.** Rode os testes (esperado: PASS) e `npx eslint src/lib/receber tests/receber`.
